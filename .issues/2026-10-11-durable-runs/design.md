# 持久智能体执行

## 范围与验收

在现有 Python 平台内增加 SQL 持久运行控制，不新增服务。SQLite 和 PostgreSQL 共用协议。现有聊天、CLI、IM、定时任务通过 AgentManager 执行时接入。原有企业工作区和工具限制继续生效，业务工具授权不能绕过既有隔离。

- 每个 agent/thread 只能有一个活动 Run。身份从服务端调用上下文确定，版本为当前 Agent 配置快照摘要。创建、领取、心跳、取消、暂停、失联收尾、恢复和最终提交均持久化。每次恢复递增 fence，旧执行拒绝工具调用、事件和提交。
- 业务工具须管理员登记并按 agent/user 授权。写工具必须审批，审批绑定 run、真实 tool_call_id、工具名、规范化参数摘要、版本和权限修订号。拒绝编辑参数、旧审批、取消后审批、撤权后执行。
- 写调用首次 STARTED，成功 SUCCEEDED 并保存结果；重复成功只重放相同结果。超时、崩溃或提交失败视为 UNCERTAIN，不自动重做。管理员人工核对后可确认成功或确认未执行，再明确恢复；审计事件保留处置。
- Run 事件有单调 seq，先保存再输出；按 run_id/after_seq 分页补拉。最终结果、终态和 done 事件同事务提交，幂等提交相同结果，不同结果拒绝。终态不以网络完成帧代替。
- 审批和恢复使用 LangGraph checkpoint，原始输入及部分结果保存在 Run。只恢复 checkpoint，不重新注入用户输入。持久审批不依赖进程内 pending 卡。没有 checkpoint 的恢复失败关闭。
- 所有读取、取消、审批和恢复验证所属用户和当前 Agent 访问权限；管理员业务授权与不确定结果处置单独验证角色。

## 实现顺序与验证

1. SQL 表与 Repo → 真实 SQLite、两个连接竞争、版本/租约/取消、审批绑定、写账本、原子提交行为测试先红后绿。
2. RunService 与中间件、AgentManager → 实际 Deep Agents 假模型图中断/恢复，旧执行与副作用边界测试。
3. API/WS 与前端重连 → HTTP 越权、seq 补拉、重复帧去重、审批恢复测试。
4. 迁移、i18n、文档 → Ruff/mypy、非 live 全量、前端类型和构建；Windows 无 make 时执行等效检查并明确差异。

## 限制

外部工具服务仍须提供自身幂等键或查询接口，平台不能保证跨系统事务恰好执行一次。不确定写操作的安全恢复以人工确认事实为前置。数据库控制能拒绝旧执行提交，不能回滚已发出的外部请求。宿主依赖 Harness 的 checkpoint 写入接口，须验证实际安装接口后实现保护，不直接编辑 site-packages。
