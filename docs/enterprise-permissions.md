# 公司、部门与员工助手

本版本采用单公司、平级部门模型，每名员工属于一个部门。公司管理员负责账号、部门、模型和部门助手配置，不设部门管理员。

## 管理员操作

1. 在「管理 → 用户 → 部门」创建部门，配置新员工个人助手的默认名称、模型和人设。默认设置只影响之后创建的个人助手。
2. 新建员工账号时选择部门。系统自动初始化个人助手；若模型提供商尚不可用，账号仍会创建，并在用户列表显示失败状态。修复模型配置后点击重试。
3. 在部门页创建部门助手，选择模型、知识库并填写人设。新助手默认是草稿，开启发布后，本部门员工才能使用。
4. 在用户列表点击「查看员工会话」，选择助手和会话。此界面只读，支持历史分页和会话产物下载，每次查看均记录实际管理员账号、目标助手和目标员工。

已有账号不会自动改变归属。管理员给已有普通用户分配部门后，启用员工工作台权限并初始化个人助手。已有普通智能体和公司共享智能体保留原有所有权及共享规则。

## 员工操作与边界

员工在助手页看到个人助手和本部门已发布的助手。个人助手允许修改名称、头像图标、简介与人设；部门助手由管理员统一配置。员工无法自行增加智能体、改变模型、连接器、技能或知识库授权。

部门助手的配置是共享定义，运行实例按「部门助手 + 员工」隔离。每位员工有独立会话、工作区文件和记忆。内部运行实例不会出现在列表中，也不能通过其 ID 直接访问。

受管助手只通过网页使用。工具限制在私有文件读写、文档文本提取、时间、待办、提问、记忆和指定知识库查询；不开放终端、浏览器、桌面、MCP、技能执行、委派或外部写入。文档读取支持 PDF、DOCX、XLSX、PPTX 和 UTF-8 文本，不调用系统命令。

聊天文件只允许访问本人运行工作区中的 `inbound/`、`artifacts/` 和 `outbound/`。系统文件、其他员工工作区、宿主机路径与路径穿越均被拒绝。管理员审查文件也遵循该边界。

## 权限变化与配置版本

调岗、停用账号、撤销发布会取消相关运行中的会话，并在后续模型调用、工具调用及输出时重新检查授权。管理员更新部门助手会提升配置版本、停止旧实例；下一次使用同步配置并重新启动，保留原有会话与文件。过期版本不能继续输出或调用工具。

历史审查允许管理员查看已经停用、调岗或撤销发布的既有会话，不新建员工实例、不执行助手。删除员工会清理其受管助手和部门运行实例。包含成员或部门助手的部门不能删除。

## 数据迁移与验证

启动时应用 v21 数据迁移，新增部门、个人助手初始化状态、部门运行绑定，以及用户和智能体的组织字段。SQLite 和 PostgreSQL 使用相同逻辑结构，老智能体标记为 `legacy`。升级前应按现有备份流程保留数据库及工作区。

本地验收使用真实 HTTP、SQLite、工作区读写与假模型运行时，覆盖账号初始化、草稿发布、跨员工隔离、配置权限、调岗、停用、审计和内部 ID 拒绝。模型服务联网和 PostgreSQL 实例验收需要部署环境另行执行。
